# vllm-serve-bench — agent contract

A time-boxed take-home: a production-style LLM inference service on vLLM, a Go
load generator and telemetry harness, and experiments written up as
Baseline → Hypothesis → Change → Benchmark → Result → Trade-off. The owner
presents it in a 30-minute walkthrough. Every artifact here is something he
must be able to defend line by line.

`CLAUDE.md` is a symlink to this file: same contract for every harness.

Read first: [docs/01-problem-statement.md](docs/01-problem-statement.md) (the
ask and its constraints), [docs/02-architecture.md](docs/02-architecture.md)
(the design, metric definitions, experiments), then
[wiki/index.md](wiki/index.md) for what has been learned since.

## Commands

```text
make build          # bin/bench
make test           # go test ./...
make race           # go test -race ./...     (CI runs this)
make cover          # coverage floor on the result-producing packages (CI)
make lint           # golangci-lint + actionlint + ruff + markdownlint (CI)
make fmt            # gofumpt + goimports (+ ruff format)
make install-tools  # pinned golangci-lint + actionlint into GOPATH/bin
make test-gpu       # `gpu`-tagged tests against a live engine; never in CI
make help
```

Before every commit: `make lint race cover`. **`go vet` is not a substitute
for `make lint`**; the suite runs gocyclo, staticcheck, errcheck, revive,
gocritic, gosec and gofumpt, none of which vet reports. If a linter "is not
installed", it is probably in `$(go env GOPATH)/bin`; the Makefile finds it
there. Tool versions are pinned in the Makefile only; CI reads them from there.

## Non-negotiables

- **No number is typed by hand.** Every figure in `docs/03-results.md`, the
  README and the slides is generated by `bench report` from a committed
  `results/<run-id>/`. If a number is not in a results directory, it does not
  go in a document.
- **Raw results are committed and never edited.** A bad run is superseded by
  a new run with a note in the worklog, not rewritten.
- **Record the engine's actual argv, not the compose file.** vLLM takes the
  last occurrence of a repeated flag; a wrapper appending a default has
  silently overridden a tuned value before. `config.json` captures what ran.
- **The SLO is chosen from baseline data**, after the baseline sweep, with the
  reasoning written down. Never set it first and then report meeting it.
- **Claims stay inside what was measured.** One consumer GPU: no NVLink, no
  DCGM profiling counters, no tensor parallelism. Anything about TP, NVLink or
  multi-node is labelled design, not result.
- **The time box is real.** Stretch items stay stretch. When something is cut,
  say so in `docs/worklog.md`.
- **Suppressions carry a reason.** `//nolint` requires a specific linter and an
  explanation (nolintlint enforces it); a `ruff: noqa` gets a comment too.
- **This is a public repo.** No LAN addresses, hostnames, tokens, or the names
  of the company or people the exercise is for. Machine-specific values go in
  the gitignored `.env.local`.

## Testing standards

These are enforced by review and, where noted, by CI.

1. **A test must fail when the fix is reverted.** Passing proves nothing on
   its own. Before claiming a fix, revert the source change, confirm the new
   test fails, restore, and say you did it.
2. **Pin the call, not just the function.** A helper tested directly while
   nothing covers the line that calls it leaves the wiring unprotected. Revert
   the call site separately and confirm something fails.
3. **No producer without a consumer.** `unused_functions_test.go` fails when
   a plain function's only caller is its own test (CI). Wire it, delete it, or
   waive it with a reason.
4. **`go test` never needs a GPU or the network.** HTTP behaviour is tested
   against `internal/fakeserver` (an in-process OpenAI-compatible SSE server
   with configurable first-token delay and inter-token interval) on loopback.
   Anything that needs a real engine is `//go:build gpu` and runs through
   `make test-gpu` on the GPU host; its output is committed under
   `results/smoke/`.
5. **The math is tested to the exact value.** Percentiles, TTFT/TPOT, goodput
   and aggregation use hand-derived fixtures with the arithmetic written in the
   test, including edge cases: n=1, n=2, ties, empty input, `completion_tokens
   < 2` (TPOT excluded), error rows (counted, never dropped). Coverage on
   `internal/{metrics,openai,prompts,report}` has an 85% floor (CI).
6. **Pure logic takes an injected clock.** Timing math is tested with fixed
   timestamps, not `time.Sleep`. The only wall-clock tests are the fake-server
   integration tests, which assert TTFT/TPOT within an explicit tolerance and
   say in a comment why that tolerance is safe.
7. **Deterministic by seed.** Prompt generation is tested for byte-identical
   output under the same seed and different output under a different one.
   Expected artefacts live in `testdata/` as golden files, regenerated only
   with `go test ./... -update` and reviewed in the diff.
8. **Table-driven, parallel, helpers marked.** `t.Parallel()` wherever state
   allows (tparallel lints it), `t.Helper()` in helpers (thelper lints it),
   test names that state the behaviour (`TestTPOTExcludesSingleTokenCompletions`).
9. **Race detector always.** CI runs `go test -race`; a data race in the load
   generator would corrupt the very numbers this repo exists to produce.
10. **Every bug fixed gets a regression test** named for the behaviour, and the
    fix commit says which test pins it.

Python (only `scripts/quantize/` so far) follows the house canon in
`ruff.toml`; tests, if any, go under `tests/` with pytest.

## Git

- Work on `main` is fine during the build; CI must be green on every push.
  Stage explicit paths, never `git add -A` or `git add .`.
- One logical change per commit; the commit log doubles as the time sheet.

## The wiki

This repo follows the LLM-wiki pattern (charter:
[raw/2026-09-12-llm-wiki-pattern.md](raw/2026-09-12-llm-wiki-pattern.md)).
Three layers:

- `raw/` — immutable sources: dropped-in documents, fetched pages (with a
  provenance header), captured notes, engine startup logs worth keeping. Read,
  never modified.
- `wiki/` — the LLM-maintained knowledge layer: `index.md` (catalog; read it
  first when answering), `log.md` (append-only chronology), and topic pages.
  The owner reads and directs; the LLM writes.
- This section is the **schema**. When a convention changes, change it here
  first.

Workflows:

- **Ingest** — a new source lands in `raw/`: read it, create or update the
  pages it touches, note contradictions inline, update `index.md`, append to
  `log.md`.
- **Query** — answer from the wiki (index → pages), citing pages. File a
  worthwhile answer back as a page so it compounds.
- **Lint** — on request: contradictions, stale claims, orphan pages, missing
  cross-references.
- **Work** — a significant finding, decision or surprise during the build is
  logged and the affected pages updated in the same commit as the work.

Conventions:

- One concept per page, kebab-case file names.
- Cross-reference with relative markdown links (they render on GitHub); no
  `[[wikilinks]]`.
- Every page appears in `wiki/index.md` with a one-line summary.
- Log entries: `## [YYYY-MM-DD] <type> | <title>`, type ∈ `ingest`, `query`,
  `lint`, `decision`, `work`.
- Status fields use `todo` | `in-progress` | `done` | `deferred` | `dropped`.
- The wiki **links to** `docs/`, code and `results/`; it never copies them.
  `docs/` is the build contract and the deliverable; the wiki is what was
  learned getting there, including what did not work.
